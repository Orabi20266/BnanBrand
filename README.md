# 🌸 BnanBrand — متجر منتجات نسائية فاخرة

متجر كامل المكدس (Full-Stack) لمنتجات نسائية أنيقة: **إكسسوارات، مجوهرات، عطور، صناديق هدايا، ومنتجات عناية**.
تصميم عربي **RTL** بخطوط أنثوية ناعمة وهوية وردية (`#E75480`، `#FFB6D9`، `#FFD7E8`)، بواجهة متجر +
لوحة تحكم أدمن + سلة مشتريات + طلبات + بريد إلكتروني تلقائي للزبون والشركة.

---

## ✨ المزايا

| الميزة | الوصف |
|---|---|
| 🛍️ واجهة المتجر | صفحات: رئيسية، منتجات (بحث/تصفية)، تفاصيل منتج، سلة، إتمام طلب، تتبع، عن/تواصل |
| 🛒 سلة مشتريات | تعمل على `localStorage` مع دعم الخيارات (المتغيرات: لون/مقاس) |
| 🔐 لوحة تحكم أدمن | إدارة المنتجات والأقسام والطلبات والإعدادات، مع رفع الصور والخصومات |
| 💌 بريد تلقائي | عند الطلب: بريد للزبون + بريد للشركة (رقم الطلب، المنتجات، الإجمالي، بيانات التوصيل) |
| 🔑 أمان | تسجيل دخول بـ JWT + تشفير + حماية المسارات الإدارية |
| 💾 قاعدة بيانات | SQLite عبر `node:sqlite` (بدون تبعيات أصلية — يعمل على Node 22+) |
| 🌐 GitHub Pages | المعاينة الثابتة للمتجر تعمل ببيانات تجريبية دون خادم |

## 🚀 التشغيل السريع (macOS)

انقري **مرتين على ملف `تشغيل الموقع.command`** — يشغّل الخادم ويفتح المتجر تلقائياً:

- المتجر: `http://localhost:4000`
- لوحة التحكم: `http://localhost:4000/admin`

## 🛠️ التشغيل اليدوي

```bash
# 1) تثبيت الحزم
npm install

# 2) تعبئة البيانات التجريبية (أول مرة فقط)
npm run seed

# 3) تشغيل الخادم
npm run start          # → http://localhost:4000
```

### لوحة تحكم الواجهة (React) أثناء التطوير

```bash
npm run dev            # يشغّل الخادم + Vite معاً (النوافذ الساخنة)
# أو بشكل منفصل:
npm run dev:client     # → http://localhost:5173/admin
npm run build          # بناء لوحة التحكم في client/dist
```

## 🔑 بيانات الدخول والحسابات

| الدور | أين؟ | الدخول |
|---|---|---|
| **أدمن** | زر «دخول المسؤول» أو `/admin` | `Bnan1` / `Bnan1234` |
| **عميل** | زر «تسجيل الدخول» في الهيدر | إنشاء حساب جديد (بريد + كلمة مرور) أو تسجيل الدخول |

- العملاء ينشئون حساباتهم من الموقع مباشرة — تُحفظ في قاعدة البيانات بدور `customer`.
- عند تسجيل دخول الأدمن من الموقع يُنقل **تلقائياً إلى لوحة التحكم** `/admin` لتعديل المنتجات والطلبات.
- واجهات الإدارة (`/api/admin/*`) محمية بدور `admin`؛ حسابات العملاء لا تصل إليها.
- دون خادم (GitHub Pages / فتح الملف مباشرة): تسجيل الدخول تجريبي محلي، وعند دخول الأدمن `Bnan1` / `Bnan1234` تُفتح واجهة إدارة المنتجات المحلية مباشرة (تُحفظ التعديلات في المتصفح).

> ⚠️ **غيّرها فوراً** من صفحة «الإعدادات» في اللوحة، وكذلك غيّر `JWT_SECRET` في `.env`.

## 🌍 النشر على GitHub Pages (معاينة المتجر فقط)

يمكنك تفعيل GitHub Pages من إعدادات المستودع (Settings → Pages ← Branch `main` / root).
- ستعمل صفحات المتجر كاملة **ببيانات تجريبية محلية** (أقسام ومنتجات وعملة شيكل).
- زر «دخول المسؤول» يُخفى تلقائياً لأن لوحة التحكم تتطلب خادماً.
- السلة تعمل، لكن **إرسال الطلبات يحتاج الخادم**.

## ☁️ النشر الكامل مع الخادم (موصى به)

استخدم منصة تشغيل Node مثل [Render](https://render.com) أو [Railway](https://railway.app) أو VPS:

1. ارفع المستودع إلى GitHub ثم اربطه بالمنصة (Start Command: `npm run start`).
2. انسخ `.env.example` إلى `.env` وضبط القيم:
   - `JWT_SECRET` ← قيمة عشوائية طويلة
   - `ADMIN_USERNAME` / `ADMIN_PASSWORD` ← بياناتك
   - `SMTP_HOST` / `SMTP_USER` / `SMTP_PASS` ← إعدادات بريدك (SendGrid/Gmail/…)
   - `CLIENT_URL` ← رابط الموقع النهائي
3. شغّل `npm run seed` مرة واحدة (أو اترك الخادم يقيسها تلقائياً إن كان ذلك مدعوماً).

> بدون إعداد SMTP تعمل الرسائل بوضع التطوير: تُسجَّل في الطرفية وقاعدة البيانات فقط.

### ⚡ نشر فوري على Render (Blueprint)

المشروع يتضمن ملف `render.yaml` جاهزاً:

1. ارفع المشروع إلى GitHub.
2. افتح: `https://dashboard.render.com/blueprints` ← **New → Blueprint Instance**.
3. اربط مستودعك — سيكتشف Render ملف `render.yaml` تلقائياً ويمرر المتغيرات لك.
4. اضبط `ADMIN_USERNAME` و `ADMIN_PASSWORD` و `SMTP_*` من تبويب **Environment** قبل أول نشر.

> الخطة `starter` تمنحك قرصاً دائماً (`/var/data`) لحفظ قاعدة البيانات والطلبات والصور.
> للتجربة المجانية: احذفي كتلة `disk` ومتغيري `DB_PATH` و `UPLOADS_PATH` من الملف.

### 🐳 نشر عبر Docker

المشروع يتضمن `Dockerfile` جاهزاً (يبني لوحة التحكم ويهيّئ البيانات عند الإطلاق):

```bash
docker build -t bnanbrand .
docker run -p 4000:4000 -e JWT_SECRET="سر-عشوائي-طويل" -e ADMIN_USERNAME=Bnan1 -e ADMIN_PASSWORD="كلمة-قوية" bnanbrand
```

للحفاظ على البيانات بين عمليات التشغيل أضف وحدة تخزين:

```bash
docker run -p 4000:4000 -v bnan-data:/var/data \
  -e DB_PATH=/var/data/bnanbrand.db -e UPLOADS_PATH=/var/data/uploads bnanbrand
```

## 🔐 قائمة فحص قبل الإنتاج

- [ ] غيّر `JWT_SECRET`
- [ ] غيّر `ADMIN_PASSWORD` من الإعدادات (أو `.env` ثم أعد تشغيل `seed`)
- [ ] اضبط متغيرات البريد `SMTP_*`
- [ ] استبدل بيانات التواصل (هاتف/واتساب/بريد/عنوان) من لوحة الأدمن
- [ ] ضع صور المنتجات الحقيقية عبر لوحة الأدمن
- [ ] وفّر HTTPS (تلقائي في Render/Railway)

## 🤖 التشغيل التلقائي (GitHub Actions)

المشروع يتضمن سيرَي عمل يعملان تلقائياً بعد كل رفع للمستودع:

| الملف | المهمة |
|---|---|
| `.github/workflows/ci.yml` | فحص وبناء على Node 22 و 24: تثبيت → بناء لوحة التحكم → إقلاع الخادم وفحص كل الصفحات (`200`) |
| `.github/workflows/pages.yml` | نشر **معاينة حية للمتجر** على GitHub Pages (بيانات تجريبية) |

لتفعيل المعاينة الحية اضبطي من إعدادات المستودع:
`Settings → Pages → Source` ← اخترِ **GitHub Actions**، ثم ارفعي أي تغيير.
